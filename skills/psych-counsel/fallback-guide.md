# Fallback 通用应答详细指引

当 wiki-rag 检索无有效结果（所有 score < 0.5）时，使用本文档的策略进行应答。

## 核心原则

1. **不暴露技术细节** — 不说"没有找到相关信息"或"数据库无结果"
2. **保持对话流畅** — 自然过渡，让用户感觉被关注
3. **继续收集信息** — 为后续可能的再次检索积累素材
4. **使用通用框架** — 基于通用心理咨询原则进行应答

## 应答策略

### 策略一：倾听与共情

**技术要点**：
- 复述/镜像用户的核心表达
- 捕捉情绪词汇并予以回应
- 表达理解而非同情

**示例**：
- "听起来你这段时间承受了很多，感到疲惫和无力是可以理解的"
- "我听到你说了好几次'不知道怎么办'，这种感觉一定让你很不安"
- "谢谢你愿意和我分享这些，这需要勇气"

### 策略二：开放式探索

**技术要点**：
- 使用开放式问题深入了解
- 聚焦用户当前最关注的方面
- 不预设方向，跟随用户的节奏

**示例**：
- "能多告诉我一些吗？当时是什么情况？"
- "这种感觉是什么时候开始的？"
- "对你来说，最困难的部分是什么？"
- "你有没有注意到什么特别会触发这种感觉？"

### 策略三：通用支持

**技术要点**：
- 正常化情绪反应
- 提供基础的情绪调节建议
- 鼓励自我关怀

**示例**：
- "很多人在类似的情况下都会有这样的感受，你并不孤单"
- "照顾好自己很重要。最近有好好吃饭、睡觉吗？"
- "有时候做一些简单的事情，比如散步、听音乐，也能帮助缓解一些"

### 策略四：信息积累

**技术要点**：
- 自然地收集关键信息
- 为后续检索构建更精确的 query
- 不让用户感觉在被"问诊"

**重点收集**：
- 持续时间和频率
- 具体的触发场景
- 对生活的影响范围
- 既往应对方式

## 再次检索时机

在以下情况下，尝试用更精确的 query 再次检索：
- 收集到更多具体信息后
- 用户描述了更明确的症状或情境后
- 对话主题发生变化后

再次检索时，使用积累的具体信息优化 query，而非重复之前的泛化 query。

## 危机兜底（最高优先级）

**在任何阶段检测到危机信号时，立即执行以下流程**：

1. **确认安全** — "你现在安全吗？"
2. **表达关心** — "我很关心你的安全，谢谢你告诉我这些"
3. **评估紧迫性** — "你有具体的计划吗？"
4. **引导求助** — "我建议你联系专业的心理援助"
5. **提供资源** — 引导拨打心理援助热线或前往最近的心理服务机构
6. **保持陪伴** — "我会在这里陪着你"

**绝对不做的事**：
- 不试图独自处理危机
- 不淡化用户的痛苦
- 不使用"想开点"、"一切都会好的"等无效安慰
- 不做出超出能力范围的承诺
